# design.md

file-review task 3.4 fixture：一份夠長的設計文件，讓「點 README 的相對連結捲動到錨點」與
「檔案樹展開狀態、捲動位置在整頁重畫時保留」等情境有足夠的內容可以捲動。

## 背景

review-repo 是專門給 `ui_preview` 假投影用的一個假 repo，本身不是真正會被建置或執行的程式碼；
它存在的唯一目的是讓檔案瀏覽功能（file-review capability）在瀏覽器裡有真實的檔案可以列目錄、
讀取中繼資料、渲染 Markdown、以及顯示各種檢視器（純文字、HTML、PDF）。

## 目標

- 涵蓋 spec 列出的主要 GFM 元素：表格、任務清單、刪除線、行內程式碼、程式碼區塊。
- 涵蓋主要檢視器種類：Markdown、純文字、HTML（含同目錄樣式表）、PDF（含中文）、二進位。
- 涵蓋根目錄推算的兩種情境：pane 的 `cwd` 在子資料夾（往上找到 `.git`）、pane 的 `cwd` 就是
  另一個根目錄本身。
- 涵蓋允許清單以外的檔案：`.gitignore` 忽略的項目、隱藏檔（`.env`）仍可直接讀取。

## 非目標

- 不測試真正的建置流程（`target/` 底下只放一個佔位檔案，不會真的被 `cargo build` 產生）。
- 不測試 Git 操作本身（`.git/` 只是一個空資料夾，讓 `find_root` 認得，不是真正的 Git 物件庫）。

## 內容清單

以下逐一列出 fixture 內每個檔案的用途，方便日後維護時對照 spec scenario：

1. `README.md`：連結（含錨點）、外部圖片、根目錄內圖片、表格、任務清單、刪除線、行內程式碼、
   程式碼區塊。
2. `docs/design.md`：本檔，含 `## 決策` 標題，內容夠長，測試捲動與錨點。
3. `docs/a.md`：一個很短的檔案，測試「同時打開多個分頁」。
4. `docs/pic.png`：一張小 PNG，測試根目錄內圖片經原始內容端點載入。
5. `long.md`：數百行內容，測試捲動位置在自動更新後仍然保留。
6. `page.html`：含 `<script>` 與同目錄 `style.css` 的 `<link>`，測試 iframe sandbox。
7. `note.txt`：含 `<b>x</b>`，測試純文字不被解讀成 HTML。
8. `bin.dat`：含 NUL 位元組，測試中繼資料把它分類成 `unsupported`。
9. `report.pdf`：3 頁、第 1 頁含中文標題，測試 PDF 檢視器與中文字型嵌入。
10. `src/`：一個資料夾，測試「展開資料夾」與圖示。

## 中間填充內容

下面這段沒有特別的測試意義，純粹是為了讓這份文件夠長、捲動有意義。

review-repo 這種「假 repo」在自動化驗收裡很常見：與其在每個測試案例裡臨時組出一份最小檔案，
不如維護一份涵蓋各種情境的固定內容，讓瀏覽器驗收腳本可以重複使用同一份 fixture、只改動其中
一兩個檔案內容來測「自動更新」，而不用每次都重新建立整個目錄結構。

這份 fixture 由 `ui_preview` 在啟動時複製到系統暫存目錄的一個唯一名稱資料夾裡，複製之後才在
副本內建立 `.git/`、`.gitignore`、`target/`、`.env` 這幾項——這幾項要嘛是 Git 拒絕直接追蹤的
路徑（`.git`），要嘛會影響到這個 repo 自己的忽略規則或建置產物（`.gitignore`、`target/`），
所以不能靜態存在於進版控的 fixture 目錄裡，只能在執行期動態補上。

驗收腳本可以自由改寫暫存副本裡的檔案內容（例如在 `long.md` 末端加一段文字），測試自動更新是否
在 3 秒內反映到畫面上，而不會弄髒這個 repo 本身的版本控制紀錄。

## 決策

以下是這份 fixture 實際採用的幾個決策，供之後維護時參考：

- **中文 PDF 的產生方式**：用 headless Chrome 的 CDP `Page.printToPDF`，從一份內嵌在產生腳本裡
  的 HTML 產生，字型使用 Windows 內建的「Microsoft JhengHei」，用 CSS 的 `break-after: page`
  分成 3 頁，第 1 頁的標題是中文。腳本與產出的 `report.pdf` 一起進版控，之後不需要每次執行時
  重新產生。
- **`.git/` 與 `.gitignore` 不放進 fixture 本體**：改在 `ui_preview` 啟動時、複製到暫存目錄之後
  才建立，理由見上一節「中間填充內容」。
- **`docs/pic.png` 不從網路下載**：以小型 PNG 產生方式在本機建立，避免依賴外部網路資源、也避免
  引入來源不明的圖片檔案。
- **兩個根目錄（`review-repo`、`other-repo`）放在同一個暫存父目錄底下**：方便 `ui_preview` 結束
  時一次刪除整個暫存父目錄，不需要分別追蹤兩個獨立的暫存路徑。
