# Direction 01：航太指揮席視覺設計

日期：2026-09-15。狀態：已選定的美術方向與視覺概念，尚未套用到正式程式介面。

## 設計定位

以「看懂多個 AI 的工作現場」為核心，結合航太儀表的精密感、觀察窗的框架與平行工作線的秩序。
介面應讓人感到清楚、可靠、專注；科技感由比例、細線與局部訊號建立。

關鍵語彙：午夜藍、霧白、冰青、分層平面、精密框線、觀察窗、克制發光。

## 色彩

下表為後續實作的建議基準；概念圖是點陣圖，不保證每個像素與色碼完全一致。

| 用途 | 色碼 | 使用方式 |
| --- | --- | --- |
| 主底色 | `#101A2A` | 品牌、主要面板與深色介面的基調 |
| 更深背景 | `#091320` | 頁面背景、輸出區與面板之間的間隔 |
| 表面層 | `#142338` | 卡片、次級分區與選取背景 |
| 主要文字 | `#E5EDF3` | 標題、任務名稱與重要數值 |
| 次要文字 | `#A3B7C9` | 說明、時間、輔助標籤 |
| 品牌強調 | `#63D5E8` | 選取、活動提示、觀察窗與關鍵輪廓 |
| 靜態框線 | `#294258` | 面板與表格分隔；低於活動高亮的視覺強度 |
| 成功 | `#39D5AC` | 明確認定的成功或通過 |
| 警示 | `#E9BC73` | 需注意、等待條件或受阻 |
| 失敗 | `#F47279` | 測試失敗與錯誤 |

冰青是品牌與活動提示，不能取代所有狀態色。狀態搭配文字及圖形，不只依賴顏色。
正式實作時，一般文字對比至少 4.5:1，大字與必要圖形至少 3:1。

## 字體與資訊層級

- 主標題與一般介面使用清楚的無襯線字體；中文保留完整、正常比例的字形。
- 時間、編號、數值、檔名與 Live Output 使用等寬字體，數值宜採等寬數字。
- 儀表板主標題最大；面板標題次之；內容、輔助說明與時間再依序降低強度。
- 英文小標可少量增加字距；中文正文不拉大字距，也不使用裝飾性的科技字體。
- 品牌封面可以大幅留白，實際資料區則優先維持閱讀密度與清楚分組。

## 面板與空間

以深藍表面的亮度差呈現層次，搭配細框線、少量切角與局部刻度。
刻度、切角與短線集中於面板外緣，不穿過文字、表格或輸出內容。

建議使用 4 px 基本間距，常用 8、12、16、24、32 px；面板間距保持一致。
一般框線以 1 px 為主，選取或活動輪廓可增加至 2 px。
小元件可採低幅度圓角；大型面板切角需克制，避免每個內層元件都重複切角。

不使用覆蓋資料的毛玻璃、掃描線、過量電路紋、星空或持續閃爍。
裝飾不得降低對比或讓介面看起來像遊戲 HUD。

## 圖示與品牌延伸

Icon 母題為「觀察窗＋三條平行工作線」。使用簡單幾何輪廓與一致線寬，保留足夠內距。
小尺寸版本移除細刻度與多餘框線，先確認 16、24、32 px 仍能辨識。
App icon 可使用深藍底、霧白觀察窗與一個冰青訊號，避免把完整儀表板塞進圖示。

Repo 封面與 OG image 放大同一母題，以層疊平面、觀察窗和工作線建立品牌。
標題置於清楚留白區，主視覺集中在另一側；必要文字限制為產品名稱與一句產品定位。
正式輸出需依目的平台檢查裁切、安全範圍與小尺寸預覽。

## 儀表板概念排列

| 位置 | 區域 | 視覺重點 |
| --- | --- | --- |
| 全寬頂列 | 名稱、agent 狀態、Add Agent、日期時間 | 精簡狀態列與清楚選取提示 |
| 左上 | Project | 專案名稱、進度、時間與 commit 分組 |
| 左下 | Tasks | 任務清單、完成標記與目前任務 |
| 中上至右上 | Pipeline | 八個站點水平排列，活動站點局部冰青高亮 |
| 中下 | Live Output | 等寬事件流、篩選、錯誤詳細與底部工作狀態 |
| 右側上層 | Files Changed | 檔名與變更標記，保持快速掃讀 |
| 右側中層 | Test Results | 通過率圓環及各狀態數值 |
| 右側下層 | Token Usage | Input／Output 長條與總量 |
| 全寬底列 | 版本、本機模式與系統狀態 | 低干擾的持續可見資訊 |

完整概念圖的八站為 Plan、Analyze、Edit、Build、Test、Debug、Polish、Complete。
此排列是使用者指定參考圖的重現，不改寫專案既有的 Stage／Workstream 模型或實作計畫。

## 狀態與動態

活動中元件可使用短暫淡入、柔和輪廓亮起或一次性的指示燈提示；穩定後保持靜止。
發光集中在目前活動站點，成功、等待與失敗保持清楚但不競爭注意力。
不以持續動畫代表虛構進度，不讓工作線自行移動或裝飾箭頭冒充依賴資料。
支援 `prefers-reduced-motion`，減少動態時直接顯示最終狀態。

HERDR runtime 的 `Done` 不等於 Task Completed；正式介面必須區分兩者。
概念圖中的 Pipeline Done 屬站點示意，不能直接映射為 runtime 狀態。

## 概念與產品功能的界線

圖中的 agent、日期、專案進度、測試結果、時間估計、版本與 token 數字均為示範資料。
Add Agent、篩選、Flow／Details 與底部輸入狀區域只表達視覺排列，不代表目前已實作。
Token Usage 須有可靠用量來源才可正式顯示；不能把 HERDR `tokens` 當成 LLM 用量。
對 HERDR 的唯讀約束與既有架構決策仍依專案權威文件辦理。

## 套用與驗收

先建立共用色彩、文字、面板與圖示規則，再延伸 repo／OG／app；避免每個輸出各自調色。
正式實作的驗收至少包含小尺寸 icon、文字對比、長檔名、密集事件、空狀態、受阻與失敗。
較窄視窗需重排區域或允許局部捲動，不將完整桌面圖縮小成不可閱讀的畫面。
概念圖作為美術與排列參考，正式版以可用性、資料來源及專案功能範圍為準。
