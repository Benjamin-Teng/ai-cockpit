# auto-update（新 capability）

## Purpose

定義已安裝的 Cockpit 如何從 GitHub Releases 取得新版：啟動器在啟動後端前檢查最新正式版、詢問使用者、下載並驗證安裝檔，
再交給安裝檔的更新模式完成替換與重新啟動，讓 SmartScreen 警告只出現在首次安裝。

## ADDED Requirements

### Requirement: 何時檢查更新

`cockpit-launch` 必須在 `desktop-launch`「啟動器」的偵測步驟判定監聽位址連不上（後端沒在執行）之後、背景啟動後端之前，
於以下條件全部成立時檢查更新；任一不成立就略過檢查、不發出任何網路請求，照常啟動：

- **由安裝檔安裝**：啟動器執行檔所在目錄有安裝檔放入的解除安裝程式。免安裝 zip、`install-desktop.ps1` 安裝與開發建置都不成立。
- **使用者沒有關閉**：環境變數 `COCKPIT_NO_UPDATE_CHECK` 未設定或為空字串。
- **距上次檢查已滿 24 小時**：上次檢查時間記在 `cockpit.log` 所在目錄的更新檢查紀錄檔；紀錄檔不存在、讀不懂或時間在未來時視為
  已滿。每次發出查詢請求前（不論之後結果如何）都更新紀錄為當下時間；寫入失敗不影響啟動。

後端已在執行（偵測為 Cockpit）時不檢查更新，只開啟視窗。

#### Scenario: 由安裝檔安裝、首次啟動

- **GIVEN** 以安裝檔安裝，資料目錄沒有更新檢查紀錄，後端沒在執行
- **WHEN** 從捷徑執行 `cockpit-launch`
- **THEN** 啟動器在啟動後端前向 GitHub 查詢最新正式版，並把當下時間寫入更新檢查紀錄

#### Scenario: 24 小時內不重複檢查

- **GIVEN** 更新檢查紀錄的時間是 3 小時前
- **WHEN** 執行 `cockpit-launch`
- **THEN** 沒有發出任何查詢請求，照常啟動後端並開啟視窗

#### Scenario: 免安裝 zip 不檢查

- **GIVEN** 從解開的 zip 目錄直接執行 `cockpit-launch`（目錄中沒有解除安裝程式）
- **WHEN** 後端沒在執行
- **THEN** 沒有發出任何查詢請求，也沒有建立更新檢查紀錄

#### Scenario: 使用者關閉檢查

- **GIVEN** 以安裝檔安裝，環境變數 `COCKPIT_NO_UPDATE_CHECK=1`
- **WHEN** 執行 `cockpit-launch`
- **THEN** 沒有發出任何查詢請求

#### Scenario: 後端已在執行

- **GIVEN** 監聽位址上已有 Cockpit 在執行
- **WHEN** 執行 `cockpit-launch`
- **THEN** 沒有發出任何查詢請求，只開啟視窗

### Requirement: 判定有無新版

系統必須以 HTTPS 向 GitHub REST API 查詢本專案的最新正式 release（不含草稿與預發布），請求帶 `User-Agent`，整個查詢
（連線、送出、讀取回應）不超過 3 秒。以下全部成立才視為有新版：

- 回應為 200，且本體是 JSON，`tag_name` 為 `v<主>.<次>.<修訂>`（三段皆為十進位整數、沒有其他後綴）；
- 該版本依主、次、修訂依序比較，大於執行中啟動器的版本；
- 資產清單中有名為 `ai-cockpit-<版本>-x64-setup.exe` 與 `SHA256SUMS.txt` 的項目。

其他情況——連線失敗、逾時、404（尚無正式版）、403／429（速率限制）、其他狀態碼、本體無法解析、版本不大於目前版本、缺少
資產——一律視為沒有新版，不顯示任何訊息，照常啟動；結果與原因寫入更新檢查紀錄檔供排查。

#### Scenario: 有新版

- **GIVEN** 執行中的版本是 `0.1.1`，最新正式 release 為 `v0.2.0` 且附上述兩個資產
- **WHEN** 啟動器檢查更新
- **THEN** 判定有新版 `0.2.0`，進入詢問

#### Scenario: 尚無正式版

- **GIVEN** API 回應 404
- **WHEN** 啟動器檢查更新
- **THEN** 不顯示任何訊息，照常啟動後端並開啟視窗

#### Scenario: 版本相同或較舊

- **GIVEN** 執行中的版本是 `0.2.0`，最新正式 release 為 `v0.2.0`
- **WHEN** 啟動器檢查更新
- **THEN** 不顯示任何訊息，照常啟動

#### Scenario: 離線

- **GIVEN** 電腦沒有網路
- **WHEN** 啟動器檢查更新
- **THEN** 3 秒內放棄，不顯示任何訊息，照常啟動

### Requirement: 詢問使用者

有新版時，系統必須以訊息框（是／否兩個選項，語言依 `ui-language` 的啟動器規則）詢問是否現在更新，內容含新版本號、目前版本號，
以及「更新時 Cockpit 會先關閉，安裝完成後自動重新開啟」的說明。選「否」或關閉訊息框時照常啟動目前版本，24 小時後的下一次
檢查會再詢問。

#### Scenario: 選擇稍後

- **GIVEN** 有新版
- **WHEN** 使用者在訊息框選「否」
- **THEN** 沒有下載任何檔案，照常啟動後端並開啟視窗

### Requirement: 下載與驗證

使用者選「是」後，系統必須：

1. 從本專案該版 release 的固定下載位置（`https://github.com/<擁有者>/<repo>/releases/download/v<版本>/<檔名>`，不採用
   API 回應中的網址）下載 `SHA256SUMS.txt`，從中找出檔名恰為 `ai-cockpit-<版本>-x64-setup.exe` 的那一行（64 位十六進位、兩個空白、
   檔名）。
2. 把安裝檔下載到使用者暫存資料夾下的 Cockpit 專用子資料夾（下載前清空），計算 SHA-256 並與上一步的值比對（不分大小寫）。
3. 任一下載失敗、逾時、檔案大於 200 MB、找不到對應行或雜湊不符時，刪除已下載的安裝檔，以錯誤訊息框說明原因並告知將繼續
   使用目前版本，使用者按確定後照常啟動目前版本。

驗證通過前，系統不得執行下載的檔案。

#### Scenario: 雜湊不符

- **GIVEN** 下載的安裝檔 SHA-256 與 `SHA256SUMS.txt` 中的值不同
- **WHEN** 驗證
- **THEN** 安裝檔被刪除、沒有被執行；跳出錯誤訊息框，按確定後照常啟動目前版本

#### Scenario: 下載中斷

- **GIVEN** 下載安裝檔時連線中斷
- **WHEN** 下載失敗
- **THEN** 跳出錯誤訊息框，按確定後照常啟動目前版本

### Requirement: 交給安裝檔

驗證通過後，系統必須以 `release-distribution`「Windows 安裝檔」的更新模式啟動下載的安裝檔（顯示進度、不詢問任何選項），
且安裝檔不繼承啟動器的標準輸入、輸出、錯誤；之後啟動器立即以 0 結束，不啟動後端、不開啟瀏覽器。後續的等候、安裝與
重新啟動由安裝檔負責。啟動安裝檔失敗時，以錯誤訊息框說明，按確定後照常啟動目前版本。

#### Scenario: 完整更新

- **GIVEN** 以安裝檔安裝了 `0.1.1`，最新正式版為 `0.2.0`，後端沒在執行
- **WHEN** 使用者從捷徑啟動並在訊息框選「是」
- **THEN** 安裝檔以更新模式執行，程式目錄的檔案換成 `0.2.0`，已安裝應用程式清單的版本為 `0.2.0`，之後 Cockpit 自動重新開啟
  （後端執行中、瀏覽器視窗開啟），整個過程沒有出現 SmartScreen 警告
