# design：output-color-tuning

## Context

動機見 `proposal.md`。現行歸色見 `cockpit-herdr/src/ansi.rs` 的 RGB→16 色函式（archive `2026-10-02-live-output-color/design.md` D4）：無彩判定為
`max − min < 64`，以整數運算實作。粗體為 `cockpit/assets/app/style.css` 的 `.ansi-bold { font-weight: 600; }`。

Claude Code 四套主題的 diff 色值取自本機安裝的 Claude Code 執行檔（2026-10-02，`diffAdded`／`diffRemoved`／`*Dimmed`／`*Word` 字串），
是決定門檻的依據；HERDR 目前把顏色量化成 16 色再輸出（`ansi-probe.md`），所以這些真彩色目前不會出現在真機。色值（`added`／`removed`／
`addedDimmed`／`removedDimmed`／`addedWord`／`removedWord`，供重算）：

| 主題 | 色值 |
|---|---|
| 深色 | (34,92,43)／(122,41,54)／(71,88,74)／(105,72,77)／(56,166,96)／(179,89,107) |
| 深色色盲友善 | (0,68,102)／(102,0,0)／(62,81,91)／(62,44,44)／(0,119,179)／(153,51,51) |
| 淺色 | (105,219,124)／(255,168,180)／(199,225,203)／(253,210,216)／(47,157,68)／(209,69,75) |
| 淺色色盲友善 | (153,204,255)／(255,204,204)／(209,231,253)／(255,233,233)／(51,102,204)／(179,0,0) |

主題與欄位的對應依執行檔中字串的出現順序推定；統計只看「每個色是否歸到其 diff 語意的色相（新增→綠或藍、刪除→紅）」，不依賴對應是否精確。

## Goals / Non-Goals

**Goals:** 帶色調但飽和度低的顏色（深色主題 diff 底色、其淡化版）歸到其色相；真正的灰仍歸灰。

**Non-Goals:** 不追求逐一還原終端機外觀；不調色相區間或明度分界。

## Decisions

### D1 無彩判定改為「絕對差 < 16 或相對差 < 10%」

以整數運算：`chroma = max − min`；`chroma < 16 || 10 * chroma < max` 為無彩。

- 絕對下限 16：各分量幾乎相同、只差一點的顏色（例如中灰 `(128,128,143)`，或極暗的 `(10,10,20)`——相對差高達 50%）不被當成有色。
- 相對 10%：接近白的淡色（例如 `(255,233,233)`，差 22、只有最大值的 8.6%）仍視為白，避免整片淡粉紅底變成紅色淡底。
- 選這組而非單純降低絕對門檻（例如 `< 24`）：深色 diff 底色 `(71,88,74)` 差只有 17，絕對門檻要降到 17 以下才分得出來，但那會讓所有
  亮色的輕微色偏（例如 `(230,230,252)`）都變成有色；相對比例同時兼顧兩端。
- 實算結果（proposal 已列）：Claude Code 24 個 diff 色 23 個正確；灰階 24 階不變；色立方 24 色由灰或白改歸有色。

### D2 粗體 700

`.ansi-bold { font-weight: 700; }`。Cascadia Mono 有 Bold，不改字型；對比不受字重影響。

## Risks / Trade-offs

- [256 色立方中 24 個原本歸灰或白的顏色改為有色] → 這些顏色本來就帶明顯色調（差 40 以上），歸色更接近終端機；目前 HERDR 不傳 256 色，無即時影響。
- [700 讓粗體在中文 fallback 字型下更粗] → 只影響帶粗體的片段；以截圖確認。
